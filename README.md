# 스타 검색

스타를 눌러 둔 GitHub 저장소 안에서 찾는 검색 사이트입니다. 화면은 포털처럼 가운데에 검색창 하나만 있습니다. 찾는 것을 적으면 관련도 순으로 후보를 보여 줍니다. 결과 행마다 라이선스 배지와 어디서 일치했는지가 붙습니다. 해석된 검색어는 칩으로 보여 줘서 방문자가 직접 지우거나 단어를 더할 수 있습니다.

기본 상태(S0)는 검색어 해석에 모델을 쓰지 않고 한국어 용어집과 영어 단어만 이해합니다. 문장을 모델이 풀어 주는 단계(S1)는 코드가 `api/`에 들어 있고, 해석 서버를 따로 띄워 주소를 넣기 전까지는 꺼져 있습니다. 계획과 수용 기준은 PRD에 있습니다.

## 점수 규칙은 repo-fit-check와 같습니다

점수 계산은 [repo-fit-check](https://github.com/junthropic/Repo-Fit-Check) 스킬의 `discover.py`를 JavaScript로 옮긴 것입니다. 관련도 70%, 최근 활동 15%, 스타 10%, 라이선스 5%로 합칩니다. 후보 안에서 드문 단어일수록 더 크게 반영합니다. 두 구현이 어긋나지 않도록 `tests/test_parity.py`가 같은 데이터와 같은 검색어로 둘을 모두 돌려 순위와 점수를 비교합니다. 점수 규칙을 바꾸면 이 테스트가 실패하므로 스킬과 사이트를 함께 고치게 됩니다.

## 로컬에서 실행하기

스타 목록을 받아 `site/stars.json`을 만들고 정적 서버로 엽니다. `gh` CLI가 로그인되어 있어야 합니다.

```bash
python scripts/build_snapshot.py --user <GitHub 계정>
python -m http.server 8765 --directory site
```

브라우저에서 `http://127.0.0.1:8765`를 열면 됩니다. 파일을 더블클릭해서 여는 방식은 데이터를 불러오지 못합니다.

스냅샷은 로그인 계정 기준 목록이 아니라 공개 엔드포인트(`users/<계정>/starred`)로 받습니다. 로그인 기준 목록에는 비공개 저장소가 섞일 수 있기 때문입니다. 주인이 나중에 비공개나 내부용으로 돌린 저장소가 목록에 보이면 오류 없이 제외합니다. 로그에는 제외한 개수만 남기고 이름은 남기지 않습니다. 저장하는 필드도 이름, 설명, 토픽, 스타, 최근 push, 라이선스, 언어, 보관·포크 여부로 한정했습니다.

## 모델 해석 (S1)

`site/config.json`의 `interpretUrl`이 `null`이면 S0와 똑같이 용어집으로만 해석합니다. 해석 서버(`api/`)를 띄워 이 값에 https 주소를 넣으면, 검색할 때 문장이 서버로 가고 모델이 풀어 준 검색어 묶음으로 검색합니다. 결과 위에는 AI가 풀었는지 용어집이 풀었는지가 적힙니다.

서버가 하는 일은 한 가지입니다. 문장(200자 이내)을 모델에 한 번 보내 영어 검색어 묶음을 JSON으로 받고, 검색어처럼 생겼는지 검사해서 돌려줍니다. 묶음은 6개까지, 묶음마다 8단어까지, 단어는 영어 소문자 한 단어여야 합니다. 모델의 지시문은 스킬의 "영어 검색어 만들기" 규칙을 옮긴 것이고, 방문자 문장은 지시가 아니라 데이터로 다룬다고 못박아 두었습니다. 모델이 이상한 답을 하면 검사에서 걸러집니다.

모델이 8초 안에 답하지 못하거나, 한도에 걸리거나, 답이 검사를 통과하지 못하면 페이지가 용어집 해석으로 돌아가고 "간이 해석"이라고 알립니다. 서버 오류가 검색을 막는 일은 없습니다.

- 한도 기본값: 방문자당 분당 8회, 방문자당 하루 모델 호출 60회, 전체 하루 1,000회. 같은 문장은 7일 동안 캐시에서 답하고 한도에 세지 않습니다. 환경 변수(`LIMIT_*`)로 바꿉니다.
- 문장은 저장하지 않고 로그에도 남기지 않습니다. 캐시 키는 정규화한 문장의 SHA-256, 방문자 구분은 소금을 섞은 주소 해시입니다. 이 두 가지는 테스트가 확인합니다. 모델을 켜면 페이지 아래에 문장이 Anthropic API로 간다는 안내가 나옵니다.
- API 키는 Worker의 비밀값에만 있고 페이지와 저장소에는 없습니다. 요청은 `ALLOWED_ORIGIN`으로 지정한 페이지에서 온 것만 받습니다. 브라우저를 거치지 않는 요청까지 막는 장치는 아니므로, 지출의 진짜 상한은 이 키 전용 워크스페이스에 건 Anthropic 지출 한도입니다.
- 기본 모델은 `claude-haiku-5-5`이고 `S1_MODEL`로 바꿀 수 있습니다. 이 계열은 temperature를 받지 않아서 같은 문장이 늘 같은 결과를 내는 것은 모델이 아니라 캐시와 공유 링크의 `g` 값(풀린 검색어)이 보장합니다.
- 한도 카운터는 Cloudflare KV에 둡니다. KV에는 원자적 증가가 없어서 동시에 들어온 요청이 한 번으로 세어질 수 있습니다. 한도는 브레이크이고 계량기가 아닙니다.

켜는 순서는 `api/wrangler.toml.example`에 있습니다. KV 만들기, 비밀값 넣기, 배포, 그리고 주소를 `site/config.json`과 `index.html`의 CSP `connect-src`에 함께 넣는 것입니다. 둘이 어긋나면 `tests/test_site.py`가 실패합니다. 지금 저장소에는 서버를 띄운 흔적도 비밀값도 없고, 실제 API 호출은 한 번도 해 보지 않았습니다. 요청 모양은 가짜 클라이언트로 검사했을 뿐입니다.

## 테스트

```bash
node --test tests/search.test.js tests/app.test.js tests/interpret-api.test.js
python -m unittest discover -s tests
```

스킬과의 일치 테스트는 이 폴더 옆의 `../repo-fit-check`를 찾습니다. 다른 위치에 있으면 `REPO_FIT_CHECK_DIR`로 알려 주세요. 스킬이 없으면 건너뛰지 않고 오류로 멈춥니다.

## 배포

`.github/workflows/daily.yml`이 매일 스냅샷을 새로 만들고, 테스트가 모두 통과하면 `site/`를 GitHub Pages에 올립니다. 테스트 작업과 배포 작업을 나누어서 배포 권한은 마지막 작업만 가집니다. 비교 테스트가 쓰는 스킬은 커밋을 고정(`SKILL_REF`)해 두었으므로, 스킬의 점수 규칙이나 용어집을 바꾸면 이 값도 같이 바꿔야 합니다.

저장소를 만들어 푸시한 뒤 Settings > Pages에서 Source를 GitHub Actions로 바꾸면 동작합니다. 조직 저장소라면 변수 `STAR_USER`에 계정 이름을 넣어야 하고, `MIN_COUNT`로 최소 저장소 수를 정해 두면 빈 응답을 그대로 배포하지 않습니다. 공개 저장소는 60일 동안 활동이 없으면 GitHub이 예약 실행을 끄므로, 사이트에 "갱신이 멈춰 있습니다"가 보이면 Actions에서 한 번 직접 실행해 주세요. 이 워크플로우는 아직 한 번도 실행해 보지 못했고 문법 검사도 하지 못했습니다.

## 한계

S0의 검색어 해석은 한국어 용어집(94개)에 있는 단어와 영어 단어만 알아듣습니다. 용어집에 없는 한국어는 결과 위에 "해석하지 못한 한국어"로 보여 주고 검색에는 쓰지 않습니다. 영어 문장에서는 am, can, the 같은 군더더기를 걷어내고, 걷어낸 말 중 검색어였을 수 있는 것(help, looking 등)과 6개를 넘어 뺀 검색어, 스타 목록 어디에도 없는 단어를 결과 위에 알려 줍니다. 자연어 문장을 제대로 알아듣는 것은 모델 해석(S1)을 켰을 때의 몫입니다.

검색 대상은 저장소 이름, 토픽, 설명이고 README 본문은 읽지 않습니다. 스냅샷은 하루에 한 번 갱신되어서 방금 뺀 별이 하루쯤 더 보일 수 있습니다. 라이선스 배지는 GitHub이 알려 준 값만 보여 줍니다. "불명"은 LICENSE 파일이 있어도 표준 라이선스로 식별되지 않았다는 뜻일 수 있으니 직접 확인해야 합니다. 결과는 후보 목록이며 어떤 저장소가 내 프로젝트에 맞는지는 판정하지 않습니다.

## 라이선스와 데이터

이 저장소의 코드는 MIT 라이선스입니다(`LICENSE`). 사이트에 나오는 저장소 이름, 설명, 토픽은 GitHub이 공개한 정보이고 각 저장소의 것입니다. 사이트는 코드를 복제하지 않고 원본으로 가는 링크만 두며, 그 저장소를 쓸 수 있는지는 해당 저장소의 라이선스가 정합니다. 목록에서 빼 달라는 요청이 있으면 스타를 취소하면 다음 갱신 때 사라집니다. 페이지에는 `noindex` 메타 태그를 넣어 검색엔진에 색인하지 말라고 요청해 두었습니다. 이것은 정중한 요청일 뿐이고, 주소를 아는 사람은 누구나 페이지와 `stars.json`을 볼 수 있습니다.
