# 스타 검색

스타를 눌러 둔 GitHub 저장소 안에서 찾는 검색 사이트입니다. 화면은 포털처럼 가운데에 검색창 하나만 있습니다. 찾는 것을 적으면 관련도 순으로 후보를 보여 줍니다. 결과 행마다 라이선스 배지와 어디서 일치했는지가 붙습니다. 해석된 검색어는 칩으로 보여 줘서 방문자가 직접 지우거나 단어를 더할 수 있습니다.

지금 만든 것은 첫 단계(S0)입니다. 검색어 해석에 모델을 쓰지 않고 한국어 용어집과 영어 단어만 이해합니다. 자연어 문장을 제대로 알아듣는 단계는 다음에 붙입니다. 계획과 수용 기준은 PRD에 있습니다.

## 점수 규칙은 repo-fit-check와 같습니다

점수 계산은 [repo-fit-check](https://github.com/junthropic/Repo-Fit-Check) 스킬의 `discover.py`를 JavaScript로 옮긴 것입니다. 관련도 70%, 최근 활동 15%, 스타 10%, 라이선스 5%로 합칩니다. 후보 안에서 드문 단어일수록 더 크게 반영합니다. 두 구현이 어긋나지 않도록 `tests/test_parity.py`가 같은 데이터와 같은 검색어로 둘을 모두 돌려 순위와 점수를 비교합니다. 점수 규칙을 바꾸면 이 테스트가 실패하므로 스킬과 사이트를 함께 고치게 됩니다.

## 로컬에서 실행하기

스타 목록을 받아 `site/stars.json`을 만들고 정적 서버로 엽니다. `gh` CLI가 로그인되어 있어야 합니다.

```bash
python scripts/build_snapshot.py --user <GitHub 계정>
python -m http.server 8765 --directory site
```

브라우저에서 `http://127.0.0.1:8765`를 열면 됩니다. 파일을 더블클릭해서 여는 방식은 데이터를 불러오지 못합니다.

스냅샷은 로그인 계정 기준 목록이 아니라 공개 엔드포인트(`users/<계정>/starred`)로 받습니다. 로그인 기준 목록에는 비공개 저장소가 섞일 수 있기 때문입니다. 비공개 항목이 하나라도 보이면 빌드가 실패합니다. 저장하는 필드도 이름, 설명, 토픽, 스타, 최근 push, 라이선스, 언어, 보관·포크 여부로 한정했습니다.

## 테스트

```bash
node --test tests/search.test.js
python -m unittest discover -s tests
```

스킬과의 일치 테스트는 이 폴더 옆의 `../repo-fit-check`를 찾습니다. 다른 위치에 있으면 `REPO_FIT_CHECK_DIR`로 알려 주세요. 스킬이 없으면 건너뛰지 않고 오류로 멈춥니다.

## 배포

`.github/workflows/daily.yml`이 매일 스냅샷을 새로 만들고, 테스트가 모두 통과하면 `site/`를 GitHub Pages에 올리도록 작성해 두었습니다. 다만 저장소를 만들어 푸시하고 Pages 설정을 켜야 동작합니다. 이 워크플로우는 아직 한 번도 실행해 보지 못했습니다.

## 한계

S0의 검색어 해석은 한국어 용어집(40개 남짓)에 있는 단어와 영어 단어만 알아듣습니다. 예를 들어 "한국 노동법 준수를 점검하는 도구 찾고 있어"는 용어집에 "법"이 없어서 `korea, labor, compliance, check`로만 해석됩니다. 그래서 컴플라이언스 도구가 먼저 나옵니다. 이때 칩에 `law`를 더하고 `compliance`와 `check`를 지우면 `korean-law-mcp`와 `legalize-kr`가 올라옵니다.

검색 대상은 저장소 이름, 토픽, 설명이고 README 본문은 읽지 않습니다. 스냅샷은 하루에 한 번 갱신되어서 방금 뺀 별이 하루쯤 더 보일 수 있습니다. 결과는 후보 목록이며 어떤 저장소가 내 프로젝트에 맞는지는 판정하지 않습니다.

라이선스는 아직 정하지 않았습니다.
